# 外部推送

用浏览器下发任务、或人不在电脑前时，Windows 的系统通知看不到。外部推送由服务端把会话的通知发到聊天机器人或手机应用，不需要任何客户端在线。

## 设置

在「设置 → 外部推送」里：

1. 打开「开启外部推送」。
2. 「添加渠道」，选类型，填写机器人或应用给出的地址、密钥，按需修改消息格式和内容，然后点「测试」确认能收到。
3. 回到会话，在输入框下方审批模式旁边的铃铛里订阅这个会话。

设置保存在服务端（数据目录的 `push.json`），对所有连接到它的设备生效。没有开启、或没有启用的渠道时，铃铛不显示。

| 渠道 | 需要填写 | 消息格式 |
| --- | --- | --- |
| 钉钉机器人 | Webhook 地址；安全设置选“加签”时填密钥，选“自定义关键词”时把关键词写进标题或正文 | 卡片（带一个按钮）、Markdown、纯文本 |
| 飞书机器人 | Webhook 地址；开启签名校验时填密钥 | 卡片（Markdown）、纯文本 |
| 企业微信群机器人 | Webhook 地址 | Markdown、纯文本 |
| Telegram Bot | Bot Token 与 Chat ID | HTML、纯文本 |
| Bark | App 里显示的地址，形如 `https://api.day.app/<Key>` | 标题与正文，点击打开的地址 |
| PushPlus | Token（建议用 PushPlus 后台的“消息 token”）；可选群组编码（一对多推送）与发送渠道（默认微信公众号，也可以是企业微信应用、邮件、浏览器插件、App） | 网页（HTML，默认是一张带额度条和按钮的卡片）、Markdown、纯文本 |
| 通用 Webhook | 地址，以及可选的 JSON 请求体。有请求体时发 POST，没有时对地址发 GET。Server酱、ntfy、Gotify 等都可以这样接入 | 自己写请求体 |

渠道可以随时编辑。地址、密钥和 Token 保存后不再显示，桌面和浏览器都读不到；编辑时留空就不修改，可选的密钥可以清除。

## 推送内容

每个渠道有自己的标题和正文，在添加或编辑渠道时修改，表单下方用示例值预览。正文按所选格式书写：Markdown 可以写 `**加粗**`、`[文字](https://…)`，HTML 可以写 `<b>`、`<a href="">`。钉钉的卡片另有按钮文字和按钮地址，Bark 另有点击后打开的地址。

| 变量 | 含义 |
| --- | --- |
| `{event}` | 事件：任务完成、任务失败、等待审批、Claude 有问题要问你 |
| `{session}` | 会话标题 |
| `{device}` | 会话所在的设备 |
| `{project}` | 项目文件夹名 |
| `{model}` | 模型 |
| `{duration}` | 这次运行的用时 |
| `{time}` | 时间，按保存设置的那台电脑或浏览器的时区 |
| `{error}` | 失败原因，只在失败时有 |
| `{quota5h}`、`{quota5hReset}` | 5 小时额度已用与重置时间 |
| `{quotaWeek}`、`{quotaWeekReset}` | 每周额度已用与重置时间 |
| `{quotaModel}`、`{quotaModelName}`、`{quotaModelReset}` | 套餐按模型单独计的每周额度已用、它的模型与重置时间，如 Max 的 Fable 每周额度：有当前模型的取它，否则取用得最多的 |
| `{url}` | 会话页面，服务端开启[浏览器访问](server-web.md)时才有 |

- 一行里的变量都没有值时，这一行不发送：比如没有失败时的“错误”一行、读不到额度时的额度一行、没开启浏览器访问时的链接一行。
- 网页格式（PushPlus 的 HTML）每行写一个完整的元素，这样省略一行时不会留下没闭合的标签；设置页按网页预览，预览里不运行任何脚本。
- 没有标题栏的格式把标题作为第一行。HTML 格式里变量的值会转义；地址里 `{url}` 原样使用，其他变量按网址编码；通用 Webhook 的请求体里按 JSON 字符串写入。
- 钉钉卡片的按钮地址为空时（如没开启浏览器访问），这条按 Markdown 发送。
- 推送不含 Claude 的回复、命令输出或文件内容；以上内容会经过所选渠道的服务商。
- 几个服务端共用一个机器人时，把服务的名字直接写进各自的模板，例如 `「{event}」公司服务器 · {session}`。

## 订阅

| 铃铛 | 推送什么 |
| --- | --- |
| 不订阅 | 不推送（除非开了下面的“未订阅的会话也推送审批和提问”） |
| 本轮 | 正在进行的这一轮、没有运行时则是下一轮：其间的审批、提问和它的结束。这一轮彻底结束后自动回到“不订阅” |
| 持续 | 这个会话之后每一轮的通知，直到改回“不订阅” |

- 订阅属于会话，桌面和浏览器看到、改的是同一个；已订阅的会话在侧栏标题旁显示同样的铃铛。
- 「新会话默认订阅」决定新建和分叉出的会话从“不订阅”还是“持续”开始；分叉不继承原会话的订阅。
- 推哪些事（等待审批、Claude 提问、任务完成、任务失败）对所有会话统一设置。主动停止的一轮不推送“完成”。
- 只剩后台任务时不推送“完成”，“本轮”订阅也不结束：Claude 在这里多半是在等构建或测试，任务结束后会自己接着做，真正做完才推送。这与窗口的系统通知不同，后者在只剩后台任务时就提醒。用后台命令一直挂着的服务（运行不会结束）因此不会推送“完成”，其间的审批和提问照常推送。
- 「未订阅的会话也推送审批和提问」：会话卡在等你回答时，没订阅也推送。可以设「延迟推送」，等待这么久仍没有在任何窗口处理才推送；订阅过的会话总是立即推送。
- 在 `ccdt` 终端里进行的轮次、服务端自己的空闲压缩不推送。

每个渠道最后一次发送失败的时间和原因显示在设置页，同时记在服务端日志里；失败不影响任务。

## 浏览器

浏览器和桌面客户端一样可以添加、编辑、删除渠道和修改其余设置：渠道的地址和密钥谁都读不回来，而持有浏览器登录的人本来就能下发命令。
