# 路线与现状

## 已完成

- 两端消息契约、离线模拟服务与界面，用于不依赖账号的开发和回归。
- 反向执行通道：WSS 登录、临时密钥、经服务地址建立的 WSS 执行通道、就绪探测、断开回收；Windows 无常驻服务、命令无弹窗；一台设备的命令共用一条 SSH 连接。
- 多设备：同一使用者的几台电脑同时在线，会话归属于项目目录所在的电脑，可接管或分叉到另一台。
- 多个连接：同一台电脑上每个连接一个独立的窗口和用户目录，各连一台服务端；本机的偏好与项目列表共用。连接之间不读取彼此的会话，也不按额度或状态自动切换。
- 断线不丢任务：运行归属于设备，断线后在服务端继续并等设备连回来；客户端自动重连并补上期间的内容；被停止或中断的一轮可以一键继续。原生终端仍随连接结束。
- 原生集成：经官方 Agent SDK 驱动未修改的 Claude Code，审批转接、运行中追加输入、会话持久化与恢复、改名、删除、分叉、主动压缩。
- 界面：三栏布局与分类设置页、项目与会话管理（置顶、更换项目、导出）、流式过程展示、提问卡片、模型 / 推理强度 / 审批模式 / 上下文、Claude Code 设置页、内嵌原生终端、账号登录与额度、调用统计、定时任务、草稿保存、系统通知、可改的快捷键、托盘后台。
- 发行与部署：Windows 安装包（自带运行组件）、Docker / Compose 部署脚本、三种 TLS 入口、备份恢复、原地升级、跟踪发布页、从客户端一键升级服务端与客户端。

各版本的变化见[变更记录](../CHANGELOG.md)。

## 已实现、尚未在真实部署中验证

- CLI 2.1.293 的 Haiku 5.5 调用与 Linux 长任务：只验证了隔离环境下的初始化和状态接口。
- 周额度统计和会话活动时间的恢复：测试通过，尚未在生产库应用。
- 后台任务：用 CLI 2.1.293 实测过“回答结束时任务仍在、任务完成后自动开始下一轮”；经服务端与界面的完整流程、结束单个任务、长时间不退出的任务尚未在真实部署中验证。等待后台任务的会话仍会挡住刷新模型列表、原生终端等需要没有运行的操作。
- 域账号的 SSH 允许名单：按用户报告的 sshd 日志修改，没有域环境可测。
- 分叉出的会话在真实 CLI 中续聊。
- Claude 经 SSH 修改 `schedules.json` 后定时任务生效；客户端长时间驻留后台时任务的准点情况。
- 服务端升级时安装新版本所需的依赖、启动失败时退回镜像版本；版本不一致的客户端在登录页升级。
- 登录限速在 nginx 反代模式下按真实来源地址区分（依赖 `X-Real-IP`）。
- 思考摘要在各模型上的显示。
- Max 订阅下按模型的每周额度（Fable）在账号页的显示：按官方接口的字段实现，尚未用 Max 账号核对。
- Claude 的提问：自动审批模式下是否同样到达界面，选择的答案是否被原生采纳。
- 更换会话项目、把会话接到另一台电脑之后，一轮中途发生自动压缩的情形。
- 断线接续：在一套真实部署上测过瞬断、静默丢包、超过宽限后继续、服务端重启、经 nginx 反代和两个会话同时运行时的断线；经代理软件的链路、长时间离线后 Claude 自行停下的表现尚未验证。
- 会话历史的合并：用一个真实的旧会话库验证过内容前后一致；更大的库所需的时间和磁盘空间只有这一个实测点。
- SSH 连接复用：在一套真实部署上测过耗时、十条以上并发和取消；大文件传输期间小命令会变慢，影响面尚未在不同带宽下评估。
- 运行数上限按内存的估算只有一个实测点。
- 重连后提示缓存的命中：原因与修复已由请求记录和单元测试确认，修复部署后的实际命中率尚未观察。
- 设置页新增的 8 个 Claude Code 设置项在经 SDK 的无界面运行中是否逐项生效。
- 连接失败的提示：杀毒软件真实拦截 sshd、执行通道建立不了、各类证书与反代错误时给出的文字，只有单元测试和本机演练。
- WSS 执行通道：本机用真实的 OpenSSH 走通了并发命令、大输出、scp、通道中断与恢复；尚未在真实网络、nginx 反代和丢包、高时延下验证。
- Windows 通知点击后回到会话、提示音开关；标题栏拖动与系统窗口按钮的贴合。
- macOS 客户端（实验性）：构建、本机 SSH 服务的自动测试和打包后的启动检查在 GitHub 的 macOS 机器上通过；一位使用者在 Mac mini 上连接真实服务端试用过基本功能。清单见 [macOS 客户端](macos.md#已验证与未验证)。
- Linux 客户端（实验性，Ubuntu LTS x64 的 deb）：自动测试、安装和安装后的启动检查在 GitHub 的 Ubuntu 机器上通过；没有在真实的桌面上使用过。清单见 [Linux 客户端](linux.md#已验证与未验证)。
- arm64 的服务端（实验性）：镜像构建、部署自测和服务端测试在 GitHub 的 arm64 机器上通过；没有在 arm64 服务器上用真实账号运行过。
- 审批模式“绕过权限”：在一套真实部署上确认过不再询问、提问卡片照常出现；交互式的原生终端是否接受这个模式尚未验证。
- 公式与 SVG 的显示：在一套真实部署上看过四种写法、矩阵与 SVG；其他模型实际输出的写法是否都能识别有待观察。
- 发布文件全部在 GitHub 上构建：0.3.0 预发布由它发出，其 Windows 安装包与服务端经应用内升级装到一套真实部署上；0.3.1 直接作为正式版发出，并经应用内升级装到同一套部署上；预发布转为正式版的一步尚未做过。
- 经系统代理连接：已用本机的测试代理验证控制连接发出 CONNECT，执行通道与它走同一条路径，尚未在常见代理软件和真实服务端之间完整走通。

## 计划

| 事项 | 说明 |
| --- | --- |
| 远程操作执行端 | 从另一台客户端经服务端操作其他设备上的会话；客户端可选开放 Web 端口；无头 Linux 执行端。见[评估记录](research/remote-access.md) |
| 终端客户端 | 把原版 CLI 接到使用者自己的终端。取舍见[评估记录](research/linux-client-and-tunnel.md) |
| 终端留在后台 | 服务端已允许每个会话各开一个终端；一个窗口目前同时只显示一个，打开期间不能切换会话 |
| 终端与图形会话打通 | 目前内嵌终端是独立的原生会话 |
| 富内容 | SVG 显示、图片与附件的会话临时传输 |
| 提示缓存保活 | 会话空闲时定时发一条很短的消息续上缓存，做成默认关闭的开关；订阅账号下有使用政策上的风险。见[评估记录](research/cache-keepalive.md) |
| 发行质量 | 安装包代码签名；macOS 的签名、公证；macOS 与 Linux 的应用内升级，发布脚本一并上传它们的安装包；Windows on ARM、Linux arm64 与其他发行版；IPv6 地址 |
| 运维 | 证书自动续期；长任务与高负载下的容量评估 |
| 重置卡 | 官方 CLI 可用 `/limit-reset`，是否提供取决于账号；SDK 没有读取张数或使用重置卡的接口，图形入口暂缓。内嵌的原生终端运行的是交互式 CLI，可在那里试用该命令（未验证） |

2026 年 10 月做过一次全项目复查，留下的结构、存储与工程方面的事项记在[复查记录](research/review-2026-10.md)，动到相关部分前先看。

## 明确不做

- 多用户、租户隔离、把订阅包装成共享 API。
- 修改或包装 Claude Code 本体，伪造运行环境特征。
- 自建第二套审批模型、上下文管理或远程执行协议。
