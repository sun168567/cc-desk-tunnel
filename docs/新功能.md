# 文件改动的彩色 diff

真实连接时，Claude 写入或修改文件的正文已经在工具入参里，并经 `tool.input.delta` 流式到达。界面在现有工具行上把这份入参画成带语法颜色的 diff。不改官方 Claude Code。后面几节是同一批界面：输入框里用 `@` 挂上本地文件并预览文本和图片，一轮改动收成清单，发出去的图片留在对话里，以及 5 小时用量的提醒和停发。

本地模拟服务不会发出 `Write` / `Edit`，所以这块面板只在真实工具调用上出现。

## 界面

工具行保持现在的摘要：动作、文件名、`+N −M`、用时。`Write`、`Edit`、`MultiEdit`、`NotebookEdit` 默认展开，下面是一块代码面板。生成过程中面板跟着变长，标题上的折叠按钮可以把它收起。

```text
已编辑  generate_manual_pdf.py    +460 −0
┌──────────────────────────────────────────┐
│ C:\...\generate_manual_pdf.py         复制 │
├──────────────────────────────────────────┤
│ + 1 │ #!/usr/bin/env python3             │
│ + 2 │ # -*- coding: utf-8 -*-            │
│ − 8 │ old_line                           │
│   9 │ unchanged                          │
└──────────────────────────────────────────┘
```

- 面板最高约 360px，超出后在面板内滚动。
- 路径过长时省略，悬停显示完整路径。
- 复制按钮复制改完后的正文，不复制原始 JSON。路径旁另外两个动作：在资源管理器中定位这一文件，用系统默认程序打开它。桌面端已有 `shell.openPath` 打开文件夹，这里同样只打开用户这次改动里的路径。
- 一轮里出现过文件改动时，这一轮末尾收成一份清单：每个文件一行，带上合计的 `+N −M`。点文件名滚到对应的 diff 并展开。同一文件被改了几次，清单里只留一行，数字相加。
- 命令、读取、搜索等工具仍显示原来的入参和输出。解析不出文件改动时，文件类工具也退回原来的 JSON。
- 摘要上的 `+N −M` 与面板里的绿行、红行一致。新建文件整份都算新增。修改文件只统计有变化的行，没改的上下文行不计入。

## 颜色

沿用现有浅色 / 深色变量，不另做一套主题。

- 新增行用成功色淡底，删除行用危险色淡底，未改行无底色。
- 行内再按语法上色：关键字、字符串、注释、数字、函数名分开。浅色和深色各一套，铺在绿底、红底上仍能读清。
- 字体用界面已有的等宽字体。

语法着色用 `highlight.js`，只注册常见语言，按扩展名选择：TypeScript、JavaScript、Python、JSON、HTML、CSS、Shell、PowerShell、Go、Rust、Java、C、C++、C#、Ruby、PHP、SQL、YAML、Markdown。这个库随 diff 面板按需加载，不进入主包。认不出的扩展名仍显示 diff，只是不上语法色。

## 数据

服务端已经发出生成中的 `tool.input.delta` 和收齐后的 `tool.input`。界面用同一套解析。

| 工具 | 入参 | 面板 |
| --- | --- | --- |
| `Write` | `file_path`、`content` | 每一行都是新增 |
| `Edit` | `file_path`、`old_string`、`new_string` | 这一段的逐行对比 |
| `MultiEdit` | `file_path`、`edits[]` | 每一处改动一块 |
| `NotebookEdit` | `notebook_path`、`old_string`、`new_source` | 有旧文则对比，否则整段算新增 |

生成过程中 JSON 往往还没闭合，不能等 `JSON.parse`。解析器把已经到达的字符串解出来，并处理 `\n`、`\"` 这类转义，正文因此一行行长出来。收齐后再定稿行号和 `+N −M`。

对比的是这次工具调用里的那一段，不是整个文件的 git diff。`Edit` 没有文件里的行号，面板行号从这段正文的第 1 行计。

两边超过约 1500 行时不做逐行对齐：先整段标删除，再整段标新增，避免比较过慢。

## 验收

- 新建文件：绿底、行号从 1 递增、摘要为 `+N −0`，关键字和字符串颜色不同。
- 修改文件：删行红底、增行绿底、未改行无底色，摘要数字与可见行一致。
- 生成未结束：面板随 `tool.input.delta` 变长，JSON 尚未闭合也能看到已到达的正文。
- 浅色与深色下，语法色在绿底、红底上都能读清。
- 对话内查找能搜到面板里的代码；复制得到改完后的正文。

## 本地文件与图片预览

现在点加号、拖入或粘贴，只会把带引号的路径写进输入框。改为输入框上方的文件卡片：名字可见，悬停能预览。图片预览的是画面本身。发给 Claude 的仍是这台电脑上的路径，由它经执行通道读取，不上传文件。

```text
┌─────────────────────────────────────────┐
│ 📄 Openai接入方案.md                    │
├─────────────────────────────────────────┤
│ 随心输入…                               │
│ +                          发送          │
└─────────────────────────────────────────┘

悬停卡片：
┌ 接入方案.md                          × ┐
│ # 标题                                  │
│ 正文前一段…                             │
└─────────────────────────────────────────┘
```

图片卡片悬停时，同一块浮层里显示图片，不再显示路径文字。

### 怎样挂上文件

- 输入 `@` 后继续打字，列出当前会话项目目录下匹配的文件。选中后收起列表，输入框里的 `@` 和已输入的筛选文字去掉，换成一张卡片。
- 加号、拖入、粘贴仍可用。资源管理器里复制来的文件用原路径；剪贴板里没有路径的图片仍存到本机后再挂上，和现在一样。
- 每张卡片显示文件名，悬停卡片本身时用提示给出完整路径。卡片上可以去掉这一份，发送前不会带上。
- 没有桌面端（浏览器开发页）时不提供 `@` 和预览，因为页面读不到本机文件。

### 预览

悬停卡片展开预览，浮层角上的关闭把它收起。预览由桌面端读取用户自己选中的那个路径。

| 文件 | 浮层里 |
| --- | --- |
| png、jpeg、gif、webp、bmp | 图片。页面只接受 `data:` 图片，所以由桌面端读出字节再交给页面 |
| 文本（含 Markdown、代码） | 开头约 32 KB，等宽字体，浮层内滚动 |
| 其他二进制 | “无法预览”，卡片仍可发送 |

单张预览不超过 8 MB。更大的图片只保留卡片和路径，不把整张图放进页面。

### 发送和草稿

输入框里只留用户打的字。发送时把每张卡片的路径用引号接在消息后面，协议不变。未发送的卡片和草稿一起按会话保存；旧的纯文本草稿照常读出。切换会话、关掉窗口后再打开，卡片还在。

发出去之后，这条用户消息下面仍留着当时的附件，不再只剩路径文字。图片显示画面，其他文件显示文件名。画面来自发送时已经读过的预览；翻历史时不再为了补一张图去读盘。超过预览大小的图片只留文件名。浏览器开发页没有这些卡片，消息仍是纯文字。

### 验收

- `@` 能在当前项目里挑文件，选中后输入框不再留着 `@` 和路径。
- 加号、拖入、粘贴得到同样的卡片，可以单张去掉。
- 悬停 Markdown 或代码，浮层里是正文开头；悬停图片，浮层里是画面。
- 发出去的消息里仍有带引号的路径。草稿切换会话后卡片还在。
- 无法识别的二进制只显示“无法预览”，不把内容塞进页面。
- 一轮改了多个文件时，末尾有一份清单；点文件名跳到对应 diff。同一文件多次改动合成一行。
- diff 标题可以在资源管理器中定位该文件，也可以用默认程序打开。
- 发送后的用户消息下面，图片仍是画面，其他附件仍是文件名。翻到更早的历史时，这些附件还在。

## 5 小时用量

账号页已经显示官方的 5 小时额度（`five_hour` 的 `utilization`，0 到 100）。在这上面加一道本机门槛，不另算一套用量，也不改官方「额度用尽后自动继续」。

默认两档：

| 已用 | 动作 |
| --- | --- |
| 达到 90% | 提醒一次。输入框上方写明已用比例和重置时间，窗口不在前台时再发一条系统通知 |
| 达到 95% | 停止新的访问：不能发送、不能点「继续」、到点的定时任务也不发出 |

已经在跑的那一轮让它跑完，不再往里追加消息。历史、设置、账号页仍可打开。额度读数降回 95% 以下，或到了官方给出的重置时间，发送自动恢复，不必手动打开。

读数为空时不拦截。API 账号没有这份订阅额度，和现在一样显示不可用，发送不受这道门槛影响。

90% 的提醒在同一个 5 小时窗口里只出现一次。用量掉回 90% 以下之后再次升上去，才再提醒。95% 的停发一直保持到恢复条件满足。

两档百分比放在「设置 → 账号与额度」，默认 90 和 95，可以改。提醒档必须低于停发档。服务端在接受新消息时用同一对数字拒绝，避免另一台电脑或定时任务绕过界面。拒绝时说明已用比例和重置时间。

### 代码

| 文件 | 职责 |
| --- | --- |
| `apps/desktop/src/AccountPanel.tsx`、`SettingsPage.tsx` | 展示 5 小时用量；设置里改提醒和停发的百分比 |
| `apps/desktop/src/Composer.tsx`、`SchedulePanel.tsx` | 90% 提醒；95% 时发送、继续和定时任务不可用，并写明原因 |
| `apps/server/src/server.ts` | 新消息到达时按同一门槛拒绝 |

### 验收

- 5 小时用量到 90% 时出现一次提醒，含已用比例和重置时间。同一窗口内不重复提醒。
- 到 95% 时不能发送、不能继续，定时任务不发出。正在跑的一轮不被掐断。
- 用量降到 95% 以下或过了重置时间后，发送恢复。
- 没有 5 小时额度读数时不拦截。
- 改掉默认百分比后，提醒和停发按新数字生效。
