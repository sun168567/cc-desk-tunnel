# 桌面客户端 Web 工作台（实验性）

本功能把完整前端和 Web 后台放在桌面客户端，供同一使用者通过浏览器操作当前桌面工作台。浏览器只连接桌面客户端，不接收现有代理服务的服务凭据，也不承担执行通道。Web 接入不改动代理服务的 `apps/server`、镜像、数据格式和消息协议。

**只维护一套前端。** 桌面窗口和浏览器共用 `apps/desktop/src/App.tsx`、页面组件、样式及同一份 `dist` 构建产物。通用页面和功能只在共享前端实现，不另建 Web 页面副本；浏览器仅增加配对入口与宿主接口适配。新增本机系统能力时，按需要补充 IPC、浏览器适配和 Web RPC 白名单，而不是复制前端。Web 标签页图标也直接引用软件的 `apps/desktop/electron/icon.png`，随同一次构建同步。

```text
局域网：浏览器 ── HTTP / WebSocket ── 桌面客户端 Web
                                       │
                                       └── 桌面现有工作台与执行通道 ── 代理服务
```

当前提供本机与局域网入口，不内置公网中继。不需要为了本功能升级代理服务；跨网络可达性由使用者自己的 VPN、组网等设施解决。

## 先在桌面客户端本机访问

本分支包含源码实现；这些步骤不代表上游发布包已经包含此功能。开发环境需要 Node.js 24；Windows 使用 PowerShell 7。在仓库根目录执行：

```powershell
npm ci
npm run setup:desktop
npm run build
npm run desktop
```

1. 在桌面客户端的登录页打开“本机设置”，或登录后进入“设置 → 常规”。
2. 找到“远程控制”，保留端口 `17890`（也可改为其他空闲端口，离开输入框即保存），先不开启“允许局域网访问”。
3. 打开“启用 Web 工作台”。点击地址旁的打开图标，浏览器自动配对并进入工作台；已有登录会直接复用。打开链接通过 URL fragment 临时携带配对码，页面读取后立即清除。手动输入 `http://127.0.0.1:17890` 时，首次访问仍需填写配对码。
4. 桌面客户端尚未连接现有代理服务时，网页显示等待桌面客户端连接。使用桌面客户端原有的服务地址、证书指纹与凭据连接代理服务后，网页进入工作台。

Web 默认关闭，退出桌面程序后停止，重启桌面后仍需手动启用。监听端口与局域网访问偏好会保存在当前桌面用户配置中；保存配置不会让下次启动自动开放 Web。所有开关更改立即生效，不设置额外的“应用更改”步骤。

## 修改端口与管理配对

- **运行中可以改端口。** 修改监听端口后，输入框失去焦点即保存并切换，无需应用按钮；成功后使用页面显示的新地址。端口范围为 1024–65535，Web 关闭时也会保存端口供下次启用使用。若新端口被占用或配置无效，设置页显示错误，原来的 Web 服务和有效配置保留，不必重新连接代理服务。切换成功时浏览器连接可能短暂中断；只改端口不会轮换配对码。
- **配对码保持稳定，登录有期限。** Web 开关、监听设置修改或桌面程序重启不会自动换码。每次配对的登录有效期为 **30 天**，访问不会顺延期限；到期后使用原码重新配对。Cookie 被清理、隐私模式结束或更换浏览器时也需重新配对。
- **可以单独撤销浏览器。** 设置中的“已配对浏览器”列出浏览器、登录时间和到期时间。点击“撤销”会立即注销该浏览器并断开它所有标签页的 Web 连接，不影响其他浏览器或桌面连接。浏览器主动退出配对会撤销自己的登录。
- **关闭不是撤销授权。** 关闭 Web 会立即停止监听并断开 Web 连接，但保留配对码和未到期的授权。重新启用后仍在有效期内的浏览器可继续访问。
- **重置配对码会撤销全部授权。** 在桌面设置点击“重置配对码”并确认，会生成新码、注销全部已配对浏览器并断开其 Web 连接。此操作不改变现有代理服务凭据或桌面的主执行连接。

浏览器 Cookie 不按端口隔离；同一主机改端口可能继续使用原 Cookie，但地址栏仍需切换到新端口。从本分支早期的无期限登录实现升级时，保留原配对码，旧浏览器需要重新配对，以建立明确的登录期限。

多个桌面连接各自管理 Web 开关、监听端口、配对码和浏览器登录。每个连接需选择不同的空闲端口；登录 Cookie 按连接配置目录隔离，访问另一连接不会替换当前连接的登录。浏览器始终控制它配对的桌面连接，连接的新建、切换和删除仍在桌面端完成。

## 再从其他局域网设备访问

打开“允许局域网访问”后立即保存生效。在浏览器打开 `http://桌面客户端的局域网IP:17890`（端口以当前设置为准），首次访问时使用已有配对码。此时桌面客户端监听 `0.0.0.0`；Windows 防火墙需要允许对应端口来自可信局域网。应用不会自动添加防火墙规则。

HTTP 局域网模式只适合可信网络。浏览器访问的是桌面客户端的 Web 地址，不是现有代理服务的地址。

VPN / 组网需要让浏览器直接到达桌面客户端的监听地址。当前入口只接受本机接口地址的 `Host` 和对应的同源 `Origin`；任意域名或 HTTPS 反代并非开箱支持。自行接入反代仍需满足这些校验并转发 WebSocket，本功能不增加反代信任配置，也不放宽来源校验。

## 数据与操作的归属

- **Web 是同一个工作台的入口。** 桌面或任意浏览器切换会话，其他已连接视图也会跟随；不是各自独立选会话的多客户端模式。未发送草稿、面板开关和布局保留在各自视图，不因其他设备的切换而覆盖。同一浏览器的标签页各自保存草稿，刷新后仍相互独立；新开标签页恢复该浏览器各会话最近保存的草稿。
- **桌面原连接保持不变。** Web 启用时才接入桌面渲染页现有的 `ProxyClient` 能力；浏览器不另建到代理服务的观察连接，不替换原连接桥、连接生命周期或自动调度。Web 关闭时不接管桌面工作台。
- **关闭浏览器不会断开桌面客户端。** 网页刷新、标签页关闭只关闭该视图；退出网页配对会注销该浏览器会话，使用同一 Cookie 的其他标签页也会断开。不重试已发送的写操作。桌面客户端主动断开现有代理服务、退出或休眠仍会影响执行。
- **项目文件保留在运行桌面客户端的电脑上。** 新建项目选择的是该电脑上的绝对目录，不会把浏览器所在设备的文件路径当成远程项目路径。选择、拖拽或粘贴附件会先上传到桌面客户端的用户数据目录 `uploads/`，再提交桌面客户端路径。单文件最多 20 MiB，累计最多 200 MiB；满后需要手动整理未使用的上传文件，不自动删除会话仍可能引用的附件。导出会话由浏览器下载到它所在的设备。
- **沿用“其他设备”的操作规则。** 在线设备的会话仍由原客户端路由到那台设备执行，Web 不新增执行端。浏览器上传的附件保存在所配对的桌面电脑上，不会自动复制到另一台设备。
- **定时任务仍由桌面原有调度器执行。** 浏览器读取桌面调度状态、编辑配置和请求立即运行，不运行另一套自动调度器；多开标签页不会重复触发到点任务。下一次运行时间与运行结果均取自桌面，桌面端未就绪时网页显示等待状态。
- **共享编辑不覆盖其他页面的更改。** Web 启用期间，定时任务按打开编辑时的文件版本保存；版本冲突会保留草稿并刷新列表，需要核对最新任务后重新打开编辑。
- **终端超时不等于启动失败。** 浏览器终端会等待原请求的最终结果：失败后释放占用，迟到成功则清理已关闭页面的终端，不重发打开操作。服务一直没有回复时，页面会提示通过桌面原有的断开、重新连接恢复，不自动中断桌面连接。
- **本机系统操作留在桌面。** 安装器、登录前的旧服务升级、系统日志、开发者工具、窗口设置和原服务凭据不通过远程 RPC 开放。Web 复用业务工作台，但不是远程桌面，项目选择使用远程路径输入，附件选择使用浏览器文件选择器。
- **配对码具有控制权限。** 这是单用户多设备功能，不是多租户或只读分享。桌面客户端持有现有代理服务凭据，浏览器使用独立 HttpOnly / SameSite 会话 Cookie。API 采用显式操作列表，并校验来源、报文大小、请求速率与会话数量。

桌面关闭 Web 后，现有代理连接与会话继续工作。临时暂停远程访问时关闭 Web；需要取消某个浏览器的权限时单独撤销，需要全部换码时重置配对码。已经发出的操作不会因关闭 Web、授权到期或撤销配对而自动撤回。

## 当前边界

Web 工作台仍属实验性功能。配对存储、登录期限、单独撤销、HTTP / WebSocket 认证及工作台同步的关键回归测试随源码提交，通过 `npm test` 运行；测试不依赖真实 Claude 账号。

同步工作台与授权调整后的真实 Claude 原生执行、长任务、审批、终端和自动调度，仍需重新完成实际环境验收。公网中继不在本功能范围内。
