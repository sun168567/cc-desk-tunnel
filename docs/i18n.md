# 界面语言与文案

用户看到的文字都在 `packages/i18n/src/locales/<语言>/<命名空间>.json`，代码里只写键。简体中文（`zh-CN`）是源语言，先写中文，再补其他语言；目前另有英文（`en`）。界面语言默认跟随系统，可在“设置 → 外观 → 界面语言”里改选，这台电脑的各个窗口、菜单和托盘一起切换。终端客户端 `ccdt` 用同一套文案，语言跟随终端的 `LC_ALL`、`LC_MESSAGES`、`LANG`（都没有时用系统的），也可以用 `ccdt config ccdt.language zh-CN|en|default` 指定。

## 写法

- **放在哪**：一个命名空间是程序的一块（如 `settings`、`upgrade`），每种语言一个同名文件；新增命名空间时在 `packages/i18n/src/catalogs.ts` 里各加一行。改了中文文案后运行 `node scripts/i18n-types.mjs`，更新键和参数的类型。
- **键**：按所在位置和用途起的语义名，小写驼峰、用点分层，如 `upgrade.progress.downloading`；不拿原文当键。字面相同、用处不同的两句话用两个键，翻译时可能不同。
- **整句**：一句话写成一条消息，变量用 `{{name}}` 放进句子里，不把几段文字和变量拼起来，否则别的语言无法调整语序。名单用 `{{names, list}}`，数字 `{{count, number}}`，日期时间 `{{at, datetime}}`，都按当前语言格式化。
- **复数**：带数量的消息用 `count` 并按 CLDR 写复数形式：中文只写 `_other`，英文写 `_one` 和 `_other`。
- **带标记的文字**：含链接、代码、粗体的句子用 react-i18next 的 `<Trans>`，消息里用具名标签（`<code>…</code>`），由 `components` 给出对应元素。
- **组件**：用 `useTranslation()` 取 `t`，语言切换时自动重画。渲染时调用的辅助函数把 `t` 作为参数传入，不在模块里直接调用：React Compiler 会按参数缓存它们的结果。不在渲染里的文字（系统通知、抛出的错误）用 `apps/desktop/src/i18n.ts` 的 `t`，取的是那一刻的语言。
- **服务端说的话**：服务端发给人看的文字一律是“短语”（phrase）：消息键加参数，如 `{ key: 'service:session.forkRunActive' }`，客户端按自己的语言显示。这些消息在 `service` 命名空间里，服务端用 `phrase('service:…', 参数)` 生成，键和参数都有类型检查。
  - 错误码 `code` 给程序判断用，短语给人看，同一个错误码可以配不同的短语。
  - 参数可以是另一个短语（先说出来再填进去），名单用 `{{titles, quoted}}`、`{{reasons, clauses}}`、`{{lost, parts}}` 这几种格式。参数名不用 i18next 保留的 `lng`、`ns`、`context`、`defaultValue`；`count` 只用于复数。
  - 外来的原文（官方 CLI 的输出、设备 shell 的答复、系统错误）作为参数原样附上，不翻译。
  - 带短语的帧（`response`、`connection.error`、`run.error`）同时带一份源语言（中文）的 `message`，由服务端用同一套文案生成：日志、旧版本的客户端（版本不一致时它们读 `connection.error`）和从前的 `ccdt` 读它。
  - 存进会话历史的话（提示、结束原因）记成短语；旧版本存下的中文原样显示。
  - 发给 Claude 的提示词不属于界面文案，用英文写在服务端。
- **帮助**：帮助的结构只写一份（`apps/desktop/src/help-content.ts`：文章、段落顺序、图、按钮通往哪里、版本标记），文字在 `help` 命名空间里按文章和段落名存放，各语言一份。帮助的文案可以是列表（JSON 数组），如一段列表的各项。文中的链接目标 `](#文章#标题)`、快捷键 `[[动作]]`、`{device}` 这类名字，各语言必须一致，标题都用显式 `id` 作链接名。
- **程序之外的文字**：macOS 的权限提示也取自文案（`desktop:macos.*`，打包时由 `scripts/macos-usage.mjs` 写成英文的 Info.plist 和中文的 `InfoPlist.strings`），由系统按它的语言显示。`ccdt` 的安装脚本（`apps/cli/install/`、`deploy/install-ccdt.*`）在程序之外运行，读不到文案，每句话就地写中英两份，按与 `ccdt` 相同的方式判断语言：中文时说中文，否则说英文；包里的 `README.txt` 中英各一半。
- **风格**：简短，只留必要的信息（见术语表下的用词）。中文用全角标点；英文用半角标点、句首大写（sentence case），按钮用动词开头，引号和撇号用排印符号（“ ” ’）。

## 检查

`npm test` 里的几组测试：

- `packages/i18n/test/catalogs.test.mjs`：各语言的键、复数形式和参数与中文一致，类型文件是最新的，非中文的文案里没有中文。
- `packages/i18n/test/literals.test.mjs`：代码里不写中文。确实要留的（离线模拟的样例回复、和旧版本数据比较用的旧文字、中文文档的锚点）记在 `packages/i18n/literals.json` 的 `kept` 里，写明数量和原因；`node scripts/i18n-literals.mjs <文件>` 列出一个文件里的中文。
- `packages/i18n/test/usage.test.mjs`：每条文案都有代码在用（写全的键、代码补全的前缀，或另一条文案的 `$t(…)`）；删掉功能时一并删掉它的文案。
- `apps/desktop/test-main/help-links.test.mjs`：帮助在每种语言里的链接都通往存在的文章和标题，文字的形式与结构相符，链接、快捷键和名字与中文一致。

开发时在网页地址后加 `?lang=en-XA`，界面显示一种拉长并加了重音的“伪语言”：没变样的文字就是漏进代码里的，挤坏的布局在别的语言里也会挤坏。桌面客户端用 Chromium 的 `--lang=<语言>` 参数指定一次运行的系统语言，测试就是这样固定用中文运行的。
