# 界面语言与文案

用户看到的文字都在 `packages/i18n/src/locales/<语言>/<命名空间>.json`，代码里只写键。简体中文（`zh-CN`）是源语言，先写中文，再补其他语言；目前另有英文（`en`）。界面语言默认跟随系统，可在“设置 → 外观 → 界面语言”里改选，这台电脑的各个窗口一起切换。

## 写法

- **放在哪**：一个命名空间是程序的一块（如 `settings`、`upgrade`），每种语言一个同名文件；新增命名空间时在 `packages/i18n/src/catalogs.ts` 里各加一行。改了中文文案后运行 `node scripts/i18n-types.mjs`，更新键和参数的类型。
- **键**：按所在位置和用途起的语义名，小写驼峰、用点分层，如 `upgrade.progress.downloading`；不拿原文当键。字面相同、用处不同的两句话用两个键，翻译时可能不同。
- **整句**：一句话写成一条消息，变量用 `{{name}}` 放进句子里，不把几段文字和变量拼起来，否则别的语言无法调整语序。名单用 `{{names, list}}`，数字 `{{count, number}}`，日期时间 `{{at, datetime}}`，都按当前语言格式化。
- **复数**：带数量的消息用 `count` 并按 CLDR 写复数形式：中文只写 `_other`，英文写 `_one` 和 `_other`。
- **带标记的文字**：含链接、粗体的句子用 react-i18next 的 `<Trans>`，在消息里写 `<0>…</0>`。
- **组件**：用 `useTranslation()` 取 `t`，语言切换时自动重画。渲染时调用的辅助函数把 `t` 作为参数传入，不在模块里直接调用：React Compiler 会按参数缓存它们的结果。不在渲染里的文字（系统通知、抛出的错误）用 `apps/desktop/src/i18n.ts` 的 `t`，取的是那一刻的语言。
- **服务端不写界面文字**：发给客户端的是代码和参数，客户端按代码显示对应语言的文字；外来的原文（官方 CLI 的输出、设备 shell 的答复、系统错误）作为参数原样附上，不翻译。发给 Claude 的提示词不属于界面文案，用英文写在服务端。
- **风格**：简短，只留必要的信息（见术语表下的用词）。中文用全角标点；英文用半角标点、句首大写（sentence case），按钮用动词开头。

## 检查

`npm test` 里的两组测试：

- `packages/i18n/test/catalogs.test.mjs`：各语言的键、复数形式和参数与中文一致，类型文件是最新的，非中文的文案里没有中文。
- `packages/i18n/test/literals.test.mjs`：代码里的中文只出现在还没迁移的文件里，且只减不增。允许的数量记在 `packages/i18n/literals.json`；把一个文件的文字移进文案后，按测试的提示调低或删掉它的数量。`node scripts/i18n-literals.mjs <文件>` 列出一个文件里还剩的中文。

开发时在网页地址后加 `?lang=en-XA`，界面显示一种拉长并加了重音的“伪语言”：没变样的文字就是漏进代码里的，挤坏的布局在别的语言里也会挤坏。桌面客户端用 Chromium 的 `--lang=<语言>` 参数指定一次运行的系统语言，测试就是这样固定用中文运行的。
