# 发布准备

本页记录仓库上传到 GitHub 之后仍待决定或待办的事项，避免遗漏。事项办完后删除对应条目，全部办完后删除本页并从[路线](roadmap.md)移除链接。

## 已定

- 仓库以整理后的内容建立了全新的根提交；此前的本地历史不上传，只在维护者本机存档。
- 许可采用 Apache-2.0，版权署名见 `NOTICE`，项目链接见 `apps/desktop/src/project.tsx`。
- `main` 只通过合并请求更新。免费账号的私有仓库不能启用分支保护，目前靠约定和维护者本机的推送钩子；仓库公开或升级套餐后改用 GitHub 的分支保护。
- 维护用的访问令牌只授权这一个仓库，保存在本机被忽略的 `.local/`，经 `gh` 使用；令牌有期限，到期后重新生成并替换文件。

## 公开之前

- [ ] **许可确认。** 公开之前可以无成本更换，公开之后更换只对新版本生效。
- [ ] **再扫一遍秘密。** `npm run check` 只认少数特征，每次公开或发布前用 gitleaks 之类的专用工具扫描将要上传的内容。
- [ ] **确认未跟踪的本机文件。** 核对 `git status --ignored` 与 `git ls-files`，本机的工作约定、需求手稿、`.local/`、`*.pem` 不应出现在跟踪清单里。

## 发布

- 已定：在本机运行 `npm run release` 构建并上传（见[开发约定](development.md#发布)），两端共用客户端的版本号。
- [ ] **自动构建。** 发布频繁后可改用 GitHub Actions 在打标签时构建（省手工，但要维护工作流，Windows 构建占用的额度按两倍计）。
- 已定：`release.json` 里的 `runtime` 是该版本所需的镜像级别，取自 `deploy/docker/runtime-level`。改动 Dockerfile、镜像入口脚本或 Node.js / frps 版本时把这个数字加一，旧镜像上的服务端就会提示在服务器上升级，而不是自行安装。只更换 Claude Code 版本不需要加：升级时会把所需版本装进数据目录。
- 仓库私有期间，服务端用一个只读令牌（Contents 只读）查询发布页，见[部署操作手册](../deploy/README.md#从客户端升级)；仓库公开后移除。
