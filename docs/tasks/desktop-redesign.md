- ☑ 三栏骨架：图标栏（会话、定时任务；底部是更新与设置）＋ 随页面变化的二级栏 ＋ 主区。窄屏下二级栏仍可收起。
- ☑ 更新按钮：有新版本（客户端安装包或服务端）时才出现在图标栏底部。
- ☑ 设置按钮的菜单：账号项（进入账号与额度）、设置、帮助、断开连接。
- ☑ 审批模式：下拉框改为每项带一行说明的菜单，仍是原生的四种模式。
- ☑ 模型与推理强度：滑条在上，模型列表收进二级。
- ☑ 定时任务页：任务列表在二级栏，主区是空状态或编辑表单。
- ☑ 设置页：左侧分类与搜索，右侧分组卡片。账号与额度、调用日志并入其中。
- ☑ 会话行：悬停出现快捷按钮与信息卡（标题、项目、最近活动时间）。

## 二、仅本地功能

- ☑ 顶部栏：自绘标题栏，后退 / 前进（会话与页面的浏览历史）、收起二级栏、菜单。菜单只放已有功能的入口：
  - 文件：新建会话、添加项目、导出当前会话、断开连接、退出。
  - 视图：收起 / 展开二级栏、切到会话 / 定时任务 / 设置、放大 / 缩小 / 重置缩放。
  - 帮助：使用说明、快捷键、项目主页、检查更新、关于（版本）。
  - “编辑”没有可放的内容，不保留。
- ☑ 帮助文案：设置页的“帮助”分类，写连接方式、审批模式的含义、定时任务的触发条件、常见问题。
- ☑ 搜索收成图标，点击展开；铃铛打开通知记录。
- ☑ 项目菜单：置顶、改显示名称（本地别名）、在资源管理器中打开。**不做**归档与移除项目：项目下的会话可能很多，误操作代价大。
- ☑ 会话置顶（本地记录）。
- ☑ 导出为 Markdown：客户端把历史分页取全后写成文件。
- ☑ 添加文件：选择、拖入或粘贴文件，把 Windows 路径插入输入框，由 Claude 经执行通道读取。图片内容块属于路线里的“富内容”，不在本批次。
- ☑ 当前 git 分支：由客户端调用本机 git 读取并显示，只读；不做切换与新建。
- ☑ 客户端设置：关闭时留在托盘、通知、记住凭据与自动登录、普通会话的默认文件夹、版本与更新。

与原计划的出入：会话行悬停的快捷按钮只放了置顶与“更多”，删除留在菜单里以免误点；分支从仓库的 `.git` 文件读取而不是调用 git 命令，本机没装 git 也能显示。

## 三、通知

窗口隐藏到托盘或失去焦点时，用 Windows 自带的通知（Electron `Notification`，即系统通知中心的 toast）提醒；点击通知恢复窗口并切到对应会话。

- ☑ 触发：任务完成、任务失败、等待审批、Claude 提问、定时任务没能发出、连接中断。
- ☑ 设置：每类一个开关，另有总开关与提示音开关。
- ☑ 通知记录：铃铛里列出最近的通知，未读有角标。
- 运行状态随 `session.updated` 到达每个会话，完成与审批不需要服务端改动。非当前会话的“提问”与“审批”在第四部分的提问事件加入之前无法区分，统一显示为“等待处理”。

## 四、联动服务端（协议升级）

- ☑ 提问卡片：Claude 的提问（`AskUserQuestion`）不再显示允许 / 拒绝，而是列出问题与选项（单选、多选、自己写），把选择按官方结构经 `canUseTool` 的 `updatedInput.answers` 返回；“不回答”按拒绝返回。运行状态带上在等审批还是等回答，侧栏与通知据此区分，不再依赖会话内容是否已缓存。
- ☑ 更换会话的项目（输入框上方的项目标签）、更改项目指向的文件夹（项目菜单，把该项目下的会话逐个移过去）：见下节。
- ☑ 设置页接入更多官方设置项，并按“上下文与记忆 / 模型与额度 / 行为 / Git”分组：提前准备压缩摘要（`precomputeCompactionEnabled`）、后台整理记忆（`autoDreamEnabled`）、子任务的提示缓存时长（`subagentPromptCacheTtl`）、备用模型（`fallbackModel`）、提问无人回答时（`askUserQuestionTimeout`）、命令输出上限（`bashOutputMaxChars`）、提交与 PR 的署名（`attribution`，只提供“不加署名”）、内置的提交与 PR 流程说明（`includeGitInstructions`）。键名与取值取自官方 SDK 的设置类型；各项在经 SDK 的无界面运行中是否生效尚未逐项验证。全局默认模型 / 推理强度及其上限与每个会话自己的选择重叠，没有加入。
- **不做** 恢复自动标题。官方接口给出的会话标题是“自定义标题、自动摘要、首条提示词”三者按此顺序取其一（`SDKSessionInfo.summary`）；手动改名经 `renameSession` 写入自定义标题之后，接口只会返回它，自动摘要不再单独给出，也没有清除自定义标题的接口。要恢复只能解析原生记录或另外调用模型，两者都不做。

- 自动审批模式下提问是否同样经 `canUseTool` 到达界面，返回的 `answers` 是否被原生采纳。
- Claude 看到更换项目的说明后是否改用新路径；系统提示词不变时缓存是否如预期命中。

### 更换项目时的提示词处理

事实（来自本项目代码与官方 SDK 的接口）：

- 系统提示词不在原生会话记录里。它由 SDK 的 `systemPrompt.append` 在每次启动 CLI 进程时给出；本项目每轮运行启动一个进程，所以每轮都会重新生成。
- 追加的这段文字里除了项目路径，还有本次连接的 SSH 配置路径，后者每次重新连接都会变化。也就是说，重新连接后的第一轮，系统提示词本来就不同于上一次。
- 压缩只把消息历史改写成摘要，不涉及系统提示词，也不存在“重建时注入”的环节；系统提示词随每个请求照常发送。压缩之后，系统提示词之后的缓存前缀本来就失效了。

做法：

1. 会话分别记录“当前项目路径”和“系统提示词里写的项目路径”（连同写它的那次连接）。更换项目只改前者，并记下 Claude 所知道的旧路径；还没有原生上下文的会话直接改，不需要说明。
2. 下一条用户消息发出时，在它前面加一段方括号里的说明（`[CC Desk Tunnel: the user moved this session …]`），作为同一轮输入的一部分；界面上只显示用户自己写的内容。说明如实署名为本客户端，不冒充原生的系统提醒。系统提示词保持不变，缓存照常命中。
3. 系统提示词里的路径在缓存前缀反正要失效的时刻跟上当前路径：观察到压缩事件之后的下一轮，或换了连接之后的第一轮。
4. 全部走官方接口（`systemPrompt.append` 与用户消息内容），不需要改 CLI。

尚未验证：一轮运行中途发生自动压缩时，这一轮余下的部分仍用旧的系统提示词，而摘要不保证保留那段说明；下一轮起由第 3 条纠正。实现后用真实会话核对。

## 明确不做

- “完全访问权限”一类跳过原生审批的模式；自定义审批配置文件。
- 归档、移除项目、AI 重新命名。
- 钩子、MCP、插件、权限规则的可视化编辑：继续在内嵌的原生终端里用官方界面处理。
- git 分支切换与新建、工作树。
- 语音、电脑操控、内置浏览器等与外层界面无关的功能。
